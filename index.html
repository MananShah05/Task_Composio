4. The Research Pipeline

Multi-agent architecture with adversarial checking, AST validation, and strict prompt injection defenses.

Stage 01
Draft Pass
Searches and fetches official developer docs. Extracts auth schemas, token scopes, self-serve credentials, rate limits, and endpoint topologies into typed JSON.
Stage 02
Adversarial Verifier
A dedicated adversary agent with separate instructions re-opens evidence links, challenges claims against known gotchas, and flags discrepancies as ok / wrong / unverifiable.
Stage 03
Revise Loop
Disputed fields return to the researcher with targeted reviewer objections. The model executes focused web searches to reconcile contradictions.
Stage 04
Human-in-the-Loop
Persistent disagreements, low-confidence answers, or suspicious injection indicators automatically set needs_human=true for operator audit.
🛡️ Security & Prompt Injection Defenses
  • Untrusted Data Isolation: All scraped web text is enclosed in strict XML data delimiters and explicitly marked as non-executable content.
  • Zero Side-Effect Tooling: The agent possesses only read-only search/fetch tools (no bash, no file write, no outbound messaging).
  • Strict Schema Coercion: Model responses pass through whitelist enum validation; control characters, markdown tags, and key-shaped strings are scrubbed.
  • SSRF Defense: All URLs are validated to be public HTTPS endpoints, rejecting localhost, RFC1918 private IPs, and cloud metadata hosts.
